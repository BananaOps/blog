Thanks for your interest in contributing to BananaOps! Every contribution is welcome.

## How to contribute

### Report a bug

<Steps>

1. **Check** that the bug is not already reported in the [issues](https://github.com/bananaops)

2. **Open an issue** with:
   - A clear, descriptive title
   - Steps to reproduce
   - Expected vs actual behaviour
   - Screenshots if relevant
   - Environment (OS, Node.js version, etc.)

3. **Wait** for feedback from the community

</Steps>

### Suggest a feature

1. Open a **Discussion** on GitHub
2. Explain the problem you want to solve
3. Propose a solution
4. Discuss it with the community

### Submit a pull request

<Steps>

1. **Fork** the repository

2. **Clone** your fork
   ```bash
   git clone https://github.com/YOUR-USERNAME/project.git
   cd project
   ```

3. **Create a branch**
   ```bash
   git checkout -b feature/my-feature
   ```

4. **Install dependencies**
   ```bash
   task install
   ```

5. **Make your changes**
   - Follow the code conventions
   - Add tests where needed
   - Update the documentation

6. **Test**
   ```bash
   task test
   ```

7. **Commit**
   ```bash
   git add .
   git commit -m "feat: add my feature"
   ```

8. **Push**
   ```bash
   git push origin feature/my-feature
   ```

9. **Open a pull request** on GitHub

</Steps>

## Code standards

### Commit messages

We use [Conventional Commits](https://www.conventionalcommits.org/):

```bash
feat: add a new feature
fix: fix a bug
docs: update the documentation
style: code formatting
refactor: refactoring with no behaviour change
test: add or update tests
chore: maintenance tasks
```

Examples:
```bash
feat(tracker): add PostgreSQL support
fix(cloudoff): handle missing time zone in uptime tag
docs(readme): update installation instructions
```

## Good practices

<Card title="Do" icon="approve-check">
  - Write tests
  - Document your code
  - Follow the conventions
  - Be respectful
  - Ask for help when you need it
</Card>

<Card title="Avoid" icon="error">
  - Oversized commits
  - Untested code
  - Breaking changes without discussion
  - Undocumented code
</Card>

## Community

### Code of conduct

Be respectful and kind. We want BananaOps to be a welcoming place for everyone.

### Communication

- **GitHub Discussions**: general questions
- **Issues**: bugs and features
- **Pull requests**: code reviews
